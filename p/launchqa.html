토스증권 · 연금저축 런칭 로그 QA

런칭 로그 421행 전수 대조, 하드 누락 0건 — 분석이 첫날부터 믿을 수 있는 연금저축 데이터

소속토스증권기간2026.07 ~ 2026.08역할로그 명세 정본화 · 런칭 전 알파 QA · 런칭 후 전수 대조 · 퍼널 이상 진단 (2026.07 ~ 08)
측정 설계데이터 품질 검증근본 원인 추적협업

상황 Situation

  • 2026년 7월 WM 도메인을 새로 맡자마자 연금저축 대고객 런칭이 코앞이었음. 인수인계 4건, 명세는 노션과 md에 흩어져 있었음

과제 Task

  • 런칭 직후 퍼널 지표는 곧바로 의사결정에 쓰이므로, 로그가 틀리면 틀린 숫자로 판단하게 됨. 런칭 전후로 로그를 끝까지 책임져야 했음

행동 Action

  • 정본화: 흩어진 명세를 GitHub md 하나로 모아 지면 명세 13개로 정리
  • 런칭 전 QA: 알파에서 재현한 로그 185건을 명세와 대조, ETF 섹션 필터 파라미터 166건 전량 미발화를 적발해 재설계 요청 → 재배포분 발화 확인
  • 런칭 후 전수 대조: 명세에서 기대 로그 421행을 뽑아 라이브와 행 단위로 대조, 명세에 없던 로그 9행 추가
  • 이상 추적: 분석가 문의 "인트로보다 약관 UV가 많다"를 로그 무결성 → 집계 윈도우 → 진입 채널 → 교정 퍼널 순서의 진단 쿼리 6종으로 규명, 다른 탭 CTA가 인트로를 건너뛰는 경로를 찾음. 1차 회신의 오류를 스스로 발견해 확정 근거로 다시 회신
  • 분석을 위한 설계: 투자성향 진단게임은 전 구간이 한 경로라 단계 구분자를 도입(명세 346 → 150행, FE 요청 7건 중 6건 반영)

결과 Result

  • 런칭 로그 하드 누락 0건(421행 전수 대조), 발견탭 클릭 로그 섹션명 부여율 배포 전 0~1% → 배포 후 97~98%
  • 퍼널 첫 진입 기준을 분석가와 확정하고 명세 17건 정정 → 이 퍼널 로그가 이후 교차 활성화 분석의 처치 기준(소개 화면 진입)이 됨

배운 점 Insight

  • 로그 품질은 한 번의 QA로 끝나지 않는다. 결함을 찾는 것보다, 같은 결함이 다음엔 사람 손을 거치지 않고 드러나게 만드는 것이 거버넌스의 일이다
