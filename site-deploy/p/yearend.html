토스증권 · 연말 절세 수요 검증

"연말이면 유저가 알아서 온다"는 전제를 데이터로 반박하고, IRP 출시 검토의 근거까지 — 연말 절세 수요 검증

소속토스증권기간2026.08 ~ 2026.09역할분석 주제 정의 · 설계 · Impala 쿼리 8종 · 사일로/그룹 위클리 발표 (2026.08 ~ 09), PO 요청 검색어 후속 분석 (2026.09), 전략 담당 요청 IRP 검색 추이 분석 (2026.10)
가설 검증수요 추정피드백 수용로그 이해

상황 Situation

  • 사일로는 4분기 프로모션의 규모·시점·성격을 정해야 했고, 월별 계획에는 "연말정산 시즌이라 유저가 몰린다"는 믿음이 이미 반영돼 있었음
  • 연금저축은 연말을 한 번도 겪어 보지 않은 상품이라 그 믿음을 확인할 실적이 없었음

과제 Task

  • 연말의 자연 수요(Organic) 크기를 알아야 프로모션을 전환 촉진에 쓸지, 수요 창출에 쓸지 정할 수 있음
  • 어려운 점: 상품 출시 전이라 직접 측정 불가 / 사일로가 이미 믿는 전제라 거기 맞는 숫자만 고르기 쉬움

행동 Action

  • 신호 정의: 상품이 없던 2023.09 ~ 2025.12, 세 번의 연말 동안 '연금' 검색과 양도세 화면 진입을 수요 신호로 선택(성격이 다른 두 집단)
  • 사전등록: 결과가 크다·중간·작다일 때 바뀔 액션과 판정 기준(평월끼리 변동 1.3~1.56배를 넘어야 시즌성 인정)을 첫 쿼리 전에 문서로 고정
  • 로그를 아는 측정: 양도세 화면 경로가 해마다 바뀌어 특정 경로의 0건을 믿지 않고 변형부터 탐색, 12월 유입을 일별로 분해해 푸시 유입을 분리
  • 리뷰 수용: 계획에서 가져온 기준 "12월 ÷ 평월 ≥ 2배"가 성장하는 계획값에선 시즌성이 없어도 넘는다는 점을 동료 리뷰에서 확인 → 폐기하고 출시 후 실측 개설 수 기준으로 재판정. 결론에 유리했던 지표도 표본 미달로 제외
  • 정정 기록: 후속 분석에서 뒤집힌 판단 6건을 정정 이력으로 남김(예: 8월 한 달 단면을 연중 규모로 읽은 오류 → 14개월 추이로 재확인)
  • 협업 확장: 공유 직후 PO가 제안한 3분면 교차표(절세·연금 검색 여부)를 추가 분석하고, 검색 로그에서 연금 관련어를 전수 추출해 기보유자를 빼고 '바로가기가 안 뜨는 검색어'만 남겨 상시 계열·연말 절세 계열 2종 키워드 목록으로 전달
  • 스스로 정정: 전략 담당의 질문(연금저축 vs IRP 검색량)에 답하다 처음 공유한 값이 연중 최저달(8월) 단면이었음을 발견해 같은 스레드에서 바로 정정하고, 기준을 전체 유저 14개월로 바꿔 다시 공유

결과 Result

  • 연말 수요는 평월의 약 2배(양도세 화면 약 1.7배)로 실재하지만 계획 기대와는 자릿수가 다름 → 전제 반박
  • 연말에 '절세' 검색자는 10배 가까이 느는데 '절세'와 '연금'을 둘 다 검색한 사람은 6배만 늘어, 연결 비율이 오히려 하락(통계적으로 유의) → 절세 관심이 연금저축으로 잘 안 이어짐(사일로 서베이 "정보 격차"와 같은 방향)
  • 9월은 인지 연결("절세하려면 연금저축"), 12월은 기존 개설자의 납입 유도라는 시점별 방향을 사일로·그룹 위클리에서 발표
  • 액션으로 연결: PO가 공유 당일 검색 태그에 '절세'를 추가했고, 이어서 요청받은 후보 키워드 목록을 개설 바로가기 클릭률 실측('연금저축'과 'irp' 사이 55배 격차) 기준으로 전달
  • 다음 사업 검토의 근거로: 전략 담당이 IRP 출시 검토 자료의 「검토 배경」에 이 데이터를 출처와 함께 그대로 사용 — IRP 검색자는 연금저축 검색자의 약 70%(14개월 중앙값, 월 60~95%), 최근 IRP 검색자 3명 중 1명은 이미 토스증권 연금저축 보유자
  • 받은 피드백: 함께 검토한 분석가가 PO에게 "유의미한 내용들이 있다"고 요약 전달, 전략 담당 "빠르고 정확한 답변 감사합니다"

배운 점 Insight

  • 판정 기준으로 쓸 숫자는 누가 언제 왜 만든 것인지부터 확인한다. 한 번의 분석이 다음 질문(IRP)의 근거가 되려면, 틀렸던 판단까지 기록으로 남겨야 한다
